---

### `secureWipe.js` 🆕 🔒 (Loophole #4)

Overwrites file with random bytes before deletion. Used everywhere keys touch disk.

```js
// Pattern:
// 1. Get file size
// 2. Write random bytes of same size (3 passes)
// 3. fs.unlinkSync()
// 4. Called in finally{} blocks AND on SIGTERM/SIGINT
```

---

### `walletLoader.js` 🔒 (Loophole #3 — Encrypted Keys at Rest)

```
Flow:
1. Read wallets.txt → validate each key
2. Encrypt ALL keys with AES-256-GCM using WALLET_PASSPHRASE from .env
3. Write encrypted blob to wallets.env (NOT plain text key=value)
4. secureWipe() wallets.txt
5. At runtime: decrypt wallets.env into memory only
6. Keys NEVER exist as plain text on disk after conversion
```

## Chunk 3 — Scraper Engine ⭐⭐⭐

### `scraper.js` 🔧 (Loopholes #7, #15, #16)

```
Changes:

Layer order REVERSED (Loophole #16 — RAM):
  Layer 1: Axios + regex scrape page HTML (lightweight, no Chromium)
  Layer 2: Axios → Etherscan API for verified contract ABI
  Layer 3: Puppeteer ONLY if both fail (with --single-process --no-sandbox, 30s timeout)
  Layer 4: Manual input fallback

Unverified contract handling (Loophole #7):
  If Etherscan ABI fetch returns "not verified":
  - Try common mint signatures in order:
    1. mint(uint256)
    2. publicMint(uint256)
    3. mint(address,uint256,uint256,bytes)  ← ERC-1155
    4. claim(uint256)
    5. purchase(uint256)
  - Simulate each with eth_call → first that doesn't revert = winner
  - Report to GUI which signature matched

ERC-721 vs ERC-1155 detection (Loophole #15):
  After ABI fetch:
  - Check for supportsInterface(0x80ac58cd) → ERC-721
  - Check for supportsInterface(0xd9b67a26) → ERC-1155
  - Adjust TX calldata accordingly
  - Display detected standard in GUI
```

## Chunk 4 — Gas & Mint Core ⭐⭐⭐⭐

---

### `flashbotsProvider.js` 🆕 🔒 (Loophole #2)

```
Proper Flashbots bundle integration:
1. Import @flashbots/ethers-provider-bundle
2. Create FlashbotsBundleProvider with auth signer (ephemeral wallet)
3. Build bundle of all mainnet wallet TXs
4. Call sendBundle() targeting next block (block + 1)
5. Wait for bundle resolution → check inclusion
6. If not included, resubmit targeting block + 2 (max 3 attempts)
7. ONLY used on Ethereum mainnet — L2s skip this entirely
8. Falls back to standard broadcast if Flashbots relay is down
```

---

### `mempoolWatcher.js` 🆕 🛡️ (Loophole #8)

```
Optional mempool monitoring:
1. Subscribe to pending TXs via WebSocket provider
2. Filter for TXs sent TO the target contract address
3. Filter for TXs sent FROM the contract owner address
4. Watch for function signatures: setActive, unpause, flipSaleState
5. On match → emit 'MINT_LIVE' event → triggers mintExecutor immediately
6. Configurable: enabled/disabled from GUI toggle
7. Uses Alchemy WebSocket endpoint (free tier supports this)
```

---

### `mintExecutor.js` 🔒🔧 (Loopholes #5, #14, #17)

```
Changes:

Staggered firing (Loophole #5):
  - Don't fire all 50 at exact same instant
  - Fire in 3 batches aligned with RPC groups
  - 50ms gap between batches
  - Each batch fires all its wallets in parallel

Allowlist detection (Loophole #14):
  Before arming, simulate mint for each wallet:
  - If revert message contains "not on allowlist" / "not whitelisted" / "invalid proof":
    → Flag wallet as NEEDS_PROOF in GUI
    → Show Merkle proof input field
  - If user provides proof, include it in TX calldata

Wallet groups (Loophole #17):
  - Wallets can be assigned to groups (A, B, C)
  - Each group can have different: quantity, gas cap
  - Default: all wallets in group A with same settings
  - Configured from GUI left panel

Anti-duplicate protection:
  - Same as before + now persisted to mintHistory on each success
  - Survives process crash
```

## Chunk 6 — Orchestrator ⭐⭐⭐⭐⭐

### `index.js` 🔒 (Loophole #1 — Testnet Mode)

```
Testnet mode:
  if (process.env.TESTNET === 'true'):
    - RPC endpoints → Sepolia (Alchemy Sepolia, Ankr Sepolia, Infura Sepolia)
    - Etherscan → Sepolia Etherscan API
    - Flashbots → DISABLED (no Sepolia support)
    - GUI banner → "⚠️ TESTNET MODE — NO REAL ETH"
    - All other logic unchanged

Auto-detect trigger (Loophole #6):
  - If trigger type = "auto-detect":
    1. Start mempoolWatcher for target contract
    2. ALSO poll contract.saleIsActive() / contract.paused() every 2 seconds
    3. Whichever fires first → trigger mint
    4. Displayed in GUI: "WATCHING... waiting for sale to go live"

Graceful shutdown:
  - SIGTERM/SIGINT → abort all pending TXs
  - secureWipe() wallets.env
  - Close all WebSocket connections
  - Log final state to mint-history.json
  - Process.exit(0)
```
